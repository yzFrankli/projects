For question 1, you will read about what it takes to add a new type to a typed
language. However, instead of considering how to do this for Typed uScheme, the
reading will discuss the process for Typed Impcore. Typed Impcore has the exact
same syntax as untyped Impcore, but now has 3 explicit types (instead of just
integers): int, bool, and unit. Unlike Typed uScheme, Typed Impcore uses a
monomorphic type system, so there are no type variables or `forall`s in any
type. Furthermore, the type system is so simple that the interpreter can figure
out each expression's type without any type annotations from the programmer in
the code, although function definitions do need to specify their return and
parameter types. Finally, the typing judgements for Typed Impcore have 3 gammas
corresponding to the 3 environments from Impcore's operational semantics: they
are type environments for global variables, functions, and formal variables.

Given that preamble, read section 6.3 about how Typed Impcore is extended with
an array type. Skip the paragraphs about array evaluation at the end of section
6.3.2 (from "Array operations expect arrays and integers..." to the end of that

-- Typed uScheme types are written in at least 3 different ways in the textbook
   (Ugh...).  The first 2 have lots of similarities, i.e., they all have some
   version of "forall" written, and type constructors are always written to the
   left of their type arguments. The third is funkier:

    (1) The concrete syntax you'll see in a Typed uScheme program (see code
        chunk 357b for some examples). For example, a function taking a
        polymorphic list and returning an integer would be written as: 
        
            (forall ['a] ((list 'a) -> int))

    (2) The abstract syntax you'll see in the ML interpreter, i.e., how a Typed
        uScheme type is represented in the interpreter. This syntax is defined
        with an algebraic data type in code chunk 357a, and an example of using
        that syntax to construct a big type is shown at the top of page 381.
        The type of the function mentioned in (1) would be written with this ML
        expression:

            FORALL (["a"], 
                    FUNTY ([CONAPP (TYCON "list", [TYVAR "a"])],

        examples. This one is really annoying because it always puts type

        mosml interpreter tells you the empty list has type "'a list" instead 
        of "list 'a"). The type of the function from (1) would be written as

            `∀α . α list → int`
